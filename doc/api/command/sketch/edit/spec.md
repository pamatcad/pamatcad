# Name
Sketch editing

# Short Description
Create and edit constrained planar geometry, dimensions, and projected references.

# Scope
Planar sketches in a three-dimensional scene. The editor behavior is defined in [Sketches](../../../../ui/sketches.md).

# Description
Sketches combine independently addressable geometry, geometric constraints, and formula-based dimensions. Closed non-construction geometry produces selectable regions for modeling commands. Underconstrained sketches are valid.

# Inputs
A construction plane or planar solid face defines the sketch frame. Geometry coordinates are local to that frame. References must belong to the specified scene and sketch unless explicitly used as external projections or dimension dependencies.

# Parameters
Geometry constructors support points, lines, rectangles, circles, arcs, ellipses, slots, fit/control-point splines, and editable text objects. Rectangle and slot constructors create ordinary constituent curves and constraints. Construction geometry is excluded from region boundaries.

Adding the same constraint kind with the same references returns the existing constraint without solving, allocating IDs, changing the revision, or invalidating previews. Reference order within the point or curve role does not distinguish duplicates; distinct constraints are not merged merely because their equations are redundant.

Constraints include coincidence, point-on-curve, fixation, equality, concentricity, midpoint, parallelism, perpendicularity, tangency, horizontal/vertical orientation, symmetry, and collinearity. Dimensions measure lengths, distances, coordinates, radii, diameters, and angles. Driving dimensions add equations; driven dimensions measure solved geometry. Redundant driving dimensions become driven; conflicting values fail without changing the working sketch.

Formulas accept numbers and expressions. Existing numeric inputs retain millimetre/degree semantics; unitless expressions use scene units. Named references bind to stable dimension IDs. Cross-sketch dependencies are acyclic. Same-sketch measurement references enter the simultaneous solve. Scale factors are dimensionless. Ellipse major/minor radii and arc spans are dimensionable. See [Implementation](../../../../dev/sketches.md) for valid constraint combinations and solver details.

Editing supports removal, split at intersections, offset, rounding, scaling, move/rotate/copy, and projection. The slot primitive takes two cap centers and a radius. The editor converts three-point outer-tip slots into this representation, while center-to-center slots select the cap centers directly; both use a final radius gesture. Center-and-line slots select the midpoint, one cap center, then the radius. Circle/arc constructions with multiple solutions use the supplied point/side to select a branch. Face projections use boundary edges, projected orthogonally along the sketch normal.

With automatic recompute, point dragging honors permanent constraints, follows the requested position when attainable, and minimizes other parameter movement. An unattainable position is fitted to the permitted motion. Coincident endpoints represent the same drag target. Drag goals are temporary and do not alter persistent constraints or DOF. With manual recompute, dragging retains the existing unsolved coordinate-edit behavior.

Line dragging supplies absolute targets for the line's `from` and `to` endpoints, solved together under the same rules. Manual recompute updates both endpoints without solving. Projected lines are read-only. The editor translates both targets from the geometry and pointer position at drag start.

Circular-edge dragging accepts a circle or arc reference through `curve`; the existing `circle` request remains supported. It supplies a cursor point. The solver first preserves the center while resizing, then permits center motion if permanent constraints prevent that; fixed geometry stays fixed. Arcs prefer unchanged endpoint angles during rim dragging and unchanged radius/sweep during center dragging. Cursor goals and preferred positions are temporary. Manual recompute changes the radius and corresponding arc endpoints around the existing center; projected circular geometry is read-only.

Distance dimensions accept two points, one point and a line (perpendicular distance to its infinite extension), or two parallel lines. A driving line-pair distance owns a parallelism equation, removed with that dimension. Driven measurements add no equations. Nonparallel line references are invalid, including edits invalidating an existing line-pair measurement. Two-line angles can explicitly select a direct, reversed, supplementary, or reversed-supplementary branch; existing signed angles retain their meaning when no branch is supplied.

Dimensions may store an annotation position in sketch coordinates. Position-only updates neither solve nor change geometry revisions, constraints, DOF, or proxies. Positions survive Finish/reopen, Cancel, and timeline replay; whole-geometry transforms also transform their dimension annotations.

Text objects retain content, exact font bytes (or the bundled Roboto default), collection face index, weight/italic selection, origin, alignment, construction flag, and evaluated length formula. `sketch.texts.update` atomically applies partial parameters to the same text ID. Omitted fields retain their values; null clears optional font or guide fields. Updates support the shared preview option. Native/WASM generate the same exact outlines and regions, including multiline text. Independent outline editing requires `sketch.texts.explode`, which releases ordinary lines/splines without changing boundary IDs or geometry. Empty/whitespace text has no region. Multiline text cannot follow a guideline; existing single-line guideline support remains available in the API.

# Preview, results and effects
Creation and reopening use a working sketch. Mutations return entity references and solve diagnostics; rendering is requested separately through `sketch.getProxy`. Recompute may be automatic or explicit; Finish performs a final solve. Finish commits one sketch entry and recomputes dependent features; Cancel discards the working copy. Open sketches may be finished but provide no bounded regions. Failed mutations preserve the previous valid working state.

`sketch.getProxy` includes exact regions by default. With `regions: false`, it skips region reconstruction and returns `regions: null`, distinguishing omitted regions from a computed empty list. Curves, points and frame are unchanged; the option also applies to preview queries. The editor uses geometry-only proxies during live updates, clears stale fills, and restores exact fills after commit or drag release.

# Topology and references

Straight text exposes `frame` with stable `bottomLeft`, `bottomRight`, `topRight`, `topLeft`, `center`, `bottom`, `right`, `top`, `left`, `diagonal1` and `diagonal2` references. Its bounds use shaped line advances and font vertical metrics, including whitespace and empty lines. Font layout drives size; the solver controls rigid placement and rotation. Frame entities accept constraints and measurements, remain construction geometry, and cannot be independently transformed or deleted. Conversion retains helpers and external constraints while releasing text-controlled sizing. Existing guideline text has no straight frame.
IDs are stable and never renumbered after deletion. Composite geometry retains independently selectable constituent entities. Centered rectangles include two construction diagonals and a constrained center point; `lines` returns the four boundary lines, while `curves` also includes the diagonals. Slots include a construction centerline and constrained midpoint. Construction helpers do not add regions. Region boundaries retain their source curve identities. Split or merged regions require explicit resolution when a previous selection becomes ambiguous. Cached support frames and projections remain available with warnings when references are lost; repair replaces the source explicitly.

Text size/origin/construction changes preserve outline identities when they are exact affine changes of the same layout. Content, font or layout changes allocate new outline identities; downstream references that cannot resolve must fail instead of selecting unrelated glyphs. Converting to ordinary geometry preserves existing region references. Text-owned outlines are protected against independent edits, constraints and dimensions until conversion; construction changes apply to the whole text object.

# Errors
Reject nonfinite/degenerate geometry, invalid references, conflicting constraints, incompatible formula units, unresolved or cyclic dimension dependencies, ambiguous names/regions, nonplanar supports, and edits outside an active working sketch. Solver failure must not silently accept unsatisfied equations.
